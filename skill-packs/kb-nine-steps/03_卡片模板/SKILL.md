# 卡片模板

## 什么时候用
制定知识卡字段，或将一张卡转换为两种格式时使用。

## 用户提供什么
一条知识、对应原文与出处。没有资料时交付空白模板，不编造示例事实。

## 一步步做
1. 一张卡只讲一件事。类型选事实、理论、观点、技巧、经验之一；状态选候选、正式、已修订之一，新卡默认候选。放进库不等于正式，正式不等于用过，用过不等于有效。用过没与帮上没独立于状态：分别记是／否／未知、有帮助／无帮助／未知，并附使用任务与效果证据；没验证效果就记未知。
2. Markdown模板如下，YAML从第一行开始，正文也存固定字段，多行可用竖线写法。
   ```markdown
   ---
   卡片编号: "【唯一编号】"
   类型: "【类型】"
   标题: "【标题】"
   正文: "【内容】"
   成立条件: "【适用边界，注明依据归属】"
   作者明说的条件: "【原文明确条件或未知】"
   AI补充提醒: "【AI建议或无】"
   未知: "【未证实事项或无】"
   来源: "【资料名及页码、段落或链接】"
   原文摘录: "【逐字摘录】"
   资料日期: "【日期或未知】"
   核对日期: "【日期或未知】"
   适用时期: "【时期或未知】"
   状态: "候选"
   被谁取代: "无"
   用过没: "未知"
   帮上没: "未知"
   ---
   ```
3. 同一张卡输出对应JSON，字段名、内容逐一一致：
   ```json
   {
     "卡片编号": "【唯一编号】",
     "类型": "【类型】",
     "标题": "【标题】",
     "正文": "【内容】",
     "成立条件": "【适用边界，注明依据归属】",
     "作者明说的条件": "【原文明确条件或未知】",
     "AI补充提醒": "【AI建议或无】",
     "未知": "【未证实事项或无】",
     "来源": "【资料名及页码、段落或链接】",
     "原文摘录": "【逐字摘录】",
     "资料日期": "【日期或未知】",
     "核对日期": "【日期或未知】",
     "适用时期": "【时期或未知】",
     "状态": "候选",
     "被谁取代": "无",
     "用过没": "未知",
     "帮上没": "未知"
   }
   ```
4. 作者原话与条件、AI补充提醒、还不知道的分开放；不把AI建议填成作者条件或混进作者原意。缺信息写“未知”，确认不适用才写“不适用”。核对日期只记实际对照原文的日期，不能用格式转换日期代替。修订后，“被谁取代”填写新卡编号。
5. 检查JSON能解析、YAML能解析，两版字段和值一致；引号、换行须正确转义。没有解析工具时注明只做了文本检查。

## 交出什么
同一卡片两版：人看、人改用Markdown；程序批量处理用JSON。筛选、查缺项、统计让程序做，不必全交AI。修改一版后同步另一版。

## 什么时候停下来问
两版内容冲突、类型无法确定或原文含义有歧义时先问用户。缺原文就保留未知，不编摘录，不升级为正式卡。
