# 传承者·蒸馏

把具名艺术家、作者、导演、音乐人或研究对象的书籍、论文、访谈和作品材料，蒸馏成可复核、可迁移、可用于写作／创作的知识资产与风格卡。

本 Skill 的对象不是“像某人说话的词库”，而是：

> 来源证据 → 作者判断 → 产生效果的机制 → 可迁移做法 → 不能越过的边界。

## 适用时机

使用本 Skill，当请求涉及：

- 从一位具名创作者的书籍、论文、访谈或作品中研究其创作方法；
- 形成可供写作、策划、导演、音乐或其他创作使用的风格卡；
- 将已有阅读笔记改造成可追溯的蒸馏包；
- 审计一套风格卡是否把来源、解释、迁移和模仿混在一起。

不把它用于：把未经授权的原文批量复制成训练语料、伪造艺术家亲历、把一篇好作品冒充跨题稳定规律，或在没有来源材料时凭印象生成“某人风格”。

## 总原则

1. 先定研究问题，再读材料；没有问题轴就不要把摘句数量当成果。
2. 来源事实、作者自述、AI解释、可迁移机制和未知边界必须分层保存。
3. 提炼作用关系，不复制词壳、口头禅、旧词、意象或表面腔调。
4. 保留作者的矛盾、条件、代价和失败；不要把复杂方法压成无条件口号。
5. 观点可以保留强度；安全、事实和风格边界在整稿／卡片完成后做后置复核，不在创作前用“太绝对”压掉已选观点。
6. 不找“人类平均值”作为风格；从具体材料、关系、冲突、机制和受众处境中形成判断。
7. 不声称“读完”或“验证有效”，除非阅读分母和真实验证证据确实支持该说法。

## 工作模式

先判断当前请求需要哪一种模式，按需加载参考文件，不同时展开所有模式：

### A. 研究蒸馏

输出来源清单、阅读范围、证据记录、主题卡和边界；不写成品文章。

### B. 风格卡构建

在研究蒸馏基础上，形成可执行的创作动作、诊断问题、失败信号和迁移限制。必须保留证据链。

### C. 写作／创作应用

先读取已通过的风格卡，再完成具体作品；不要把内部证据、页码、候选状态和审计字段写进公开作品。作品完成后再做语义、来源和风格边界复核。

### D. 审计与修复

检查来源忠实、证据承重、解释身份、重复卡、过度主张和模仿风险；只修有证据的问题，不因偏好把风格改成平均化语言。

## 标准流程

### 1. 定义对象与产出

记录：研究对象、材料范围、目标产出（知识卡／风格 Profile／文章／创作 brief）、目标受众、允许的创作距离、来源权利状态和停止条件。

若对象是仍在世或当代创作者，默认做高层机制与转化后的创作方向，不做逐句、逐段或可替代原作者的新作仿写。

### 2. 建立来源清单

为每个来源分配稳定 `source_id`，记录标题、作者、材料类型、版本／日期、来源位置、字节数与 SHA-256（能取得时）。运行 `scripts/build_source_manifest.py` 可生成基础清单。

来源类型决定可回答的问题：随笔偏向自我解释，人物文章偏向事件与关系，论文偏向概念与边界，作品偏向实际效果。不要让一种材料冒充另一种材料。

### 3. 先提出可被材料推翻的问题

提出 2–5 个研究问题或假设，例如：

- 某种语言变化怎样产生亲近感，而不只是“看起来有古意”？
- 作者如何在受众、合同和作品质量之间取舍？
- 哪种熟悉结构中的变化能被听众感知？

问题必须能被材料支持、限制或推翻；不要先写结论再挑证据。

### 4. 分层阅读与抽取

先做目录、关键词、章节和页码导航，再对承重页深读。扫描件或 OCR 只能作为导航；承重判断需回到可读页面或连续文本。需要把 PDF 变为带页码文本时，可使用 `scripts/extract_pdf_text.py`。

记录实际阅读分母：哪些来源做了全量导航，哪些只读代表章节，哪些页或版本没有覆盖。阅读范围不完整时，卡片必须保留这个未知。

### 5. 形成证据胶囊

每个承重判断至少保留一段连续摘录及稳定定位。证据记录需要：`source_id`、页码／时间码、原文、摘录哈希、提取方法、质量说明和它支持的具体主张。

不要用单个金句承载整套方法；如果主张包含“能力、效果、代价”三个部分，就分别找证据，或收窄主张。

### 6. 四层蒸馏

每张卡严格分开：

1. **来源观察**：原文明确出现了什么，保持作者与材料身份。
2. **AI 解释**：把多个观察放在一起后的解释，可以被反驳，不伪装成作者原话。
3. **可迁移机制**：换到今天的写作／创作时，保留哪种作用关系、动作和判断顺序。
4. **边界与反例**：什么条件下不能迁移，哪类材料会推翻或收窄判断。

### 7. 从表面特征下沉到作用机制

对每个候选特征连续追问：

1. 它在材料中具体是什么？
2. 它改变了谁的感受、理解或行动？
3. 它通过什么关系、节奏、限制或代价产生效果？
4. 换一个题目时，什么必须保留，什么可以替换？
5. 没有这个条件时会怎样失败？

只有回答到作用关系，才进入风格卡。仅有“豪气、古意、幽默、口语、诗性”等标签，不足以成为可执行规则。

### 8. 保留矛盾与失败

寻找同一对象在不同材料中的张力：快写与慢修、市场与质量、亲近与距离、传统资源与现代生活等。矛盾不是噪声，而是方法的条件结构。

失败案例必须说明失败发生的场景，不能从一次实验失败推出全媒介禁令。负面规则只删除真正破坏作用的做法，不误杀同一手段在正确语境中的正向能力。

### 9. 生成知识卡与风格 Profile

每张知识卡使用 `references/card-schema.md` 的字段；风格 Profile 使用 `references/style-profile-guide.md`。Profile 只回答“创作时怎么做”，知识卡回答“为什么这样做、证据在哪里、什么时候不要这样做”。

Profile 至少包含：创作目标、核心机制、可执行动作、诊断问题、失败信号、替代做法、迁移边界和来源卡 ID。不要把作者身份、未证实经历或 AI 推测写成使用者亲历。

### 10. 后置审计

用 `scripts/validate_distillation_package.py` 做结构和证据哈希校验，再人工检查：

- 每条承重判断是否能回到证据；
- 解释是否超出来源；
- 迁移是否仍保留条件和代价；
- 是否把不同材料类型混成同一种事实；
- 是否存在重复卡或同一来源多条去向；
- 是否把风格机制变成表面仿写；
- 公开作品是否泄露内部字段或未经授权的长引文。

审计通过只代表蒸馏包结构与边界合格，不代表作者本人认可，也不代表跨题创作已经有效。真实创作反馈必须另行记录。

## 推荐交付结构

```text
distillation-package/
├── SKILL_OUTPUT_SUMMARY.md
├── source_manifest.json
├── evidence_records.jsonl
├── distillation_cards.jsonl
├── style_profile.md
├── style_profile.json
└── audit_report.md
```

可只交付当前模式需要的文件，但不要把来源、解释、风格 Profile 和公开文章覆盖成一个文件。详细字段见：

- [卡片合同](references/card-schema.md)
- [风格 Profile 指南](references/style-profile-guide.md)
- [审计清单](references/audit-checklist.md)

## 停止条件

达到用户指定产出、每条承重主张有足够证据、未知已标明、重复路由已决定、后置审计通过，就停止。不要为了“更像”无限吞材料；新增材料只有在会改变判断、边界或证据质量时才继续读取。
