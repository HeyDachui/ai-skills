# 零基础引导访谈

用户不知道表情包怎样制作、只给出一句模糊请求，或缺少会改变路线的基本信息时读取。目标是让用户不懂专业术语也能在2—4轮内进入一个可执行的小样路线，不是把生产合同改成问卷。

## 1. 什么时候启动

启动条件：

- 用户只说“帮我做表情包”“把它做成表情”；
- 用户明确说不知道该选什么、没有经验；
- 不清楚用户是从零建角色、用已有形象、扩展旧套装、做互动，还是做动态／平台包；
- 用户提供的材料身份会改变“图像生成”或“真实源文件编辑”路线。

跳过条件：

- 用户已经说明角色、材料、用途、目标结果和当前动作；
- 当前只是取回、检查、返修、打包或平台反馈；
- 答案能从附件、现有母版或状态文件直接得到。

## 2. 访谈规则

- 一轮只问一个主要问题，不一次抛出完整表单。
- 每个选择题提供3—5个普通人能理解的选项。
- 用户可以直接回复序号、自然语言或“不知道，请你推荐”。
- 给出推荐时说明一句理由，不把专业判断全部推回用户。
- 不向零基础用户展示`audit`、`master`、`pilot`等内部模式名。
- 已经从图片或文件看出的事实不重复询问。
- 用户选择后只进入相关分支，不继续询问无关字段。
- 通常2—4轮形成方向；信息足够时立即停止访谈。
- 访谈只确定生产方向，不自动公开、上传或提交平台。

## 3. 第一次回复模板

用户没有给出清楚路线时，优先使用下面这段；根据已知材料删掉不适用选项，不机械照抄。

```text
我可以带您一步一步完成。您现在更想做哪一类表情包？

1. 从零设计一个新角色和表情包
2. 把已有的人物、宠物、品牌或吉祥物做成表情包
3. 扩展一套已经存在的表情包
4. 制作两个角色之间的互动表情
5. 把现有表情做成动态，或整理成平台上传包

您可以直接回复序号；如果不确定，也可以把现有图片或文件发给我，我来判断适合哪条路线。
```

## 4. 五条用户路线

### 路线1｜从零设计角色

依次只问当前必要问题：

1. 角色来源：人物、动物、物品拟人、品牌符号，还是由Skill推荐；
2. 主要用途：日常聊天、品牌传播、内容账号、平台投稿，还是尚未确定；
3. 性格倾向：温暖可爱、活泼搞怪、冷静克制、嘴硬心软、专业可靠，或自由描述；
4. 已经确定且不能改变的品牌色、象征、服装或身份。

没有视觉母版时，角色形象必须通过图像生成能力形成。默认先生成少量母版候选，选定身份后再做3张表情小样。

### 路线2｜把已有形象做成表情包

先请用户上传或指出现有材料，然后询问材料身份：

```text
您现在的材料更接近哪一种？

1. 一张普通图片或照片
2. 多张角色参考图
3. 已确认的角色母版
4. 真实PSD／ORA等可编辑源文件
5. 不确定，请帮我判断
```

- 普通图片、PNG、JPG或联系板只作参考；所有新角色视觉使用图像生成能力。
- 只有真实模板或同版本真正可编辑源文件才允许直接编辑复用。
- 接着只确认主要用途、允许的夸张程度和绝对不能改变的特征。
- 默认先做3张高信息量小样，不直接批量生产。

### 路线3｜扩展已有表情包

先取得当前套装、母版和已采用范围，再问用户最希望补什么：

1. 高频聊天动作；
2. 更有传播感的搞怪动作；
3. 缺失的情绪；
4. 与另一个角色互动；
5. 不确定，由Skill根据现有覆盖找缺口。

不重做已经通过的同一版本。新增角色视觉仍使用图像生成能力；真实可编辑源存在时按用户要求局部编辑。

### 路线4｜双角色互动

先取得两个角色各自的母版，再问关系类型：

1. 朋友／搭档；
2. 照顾与被照顾；
3. 吐槽与回应；
4. 合作、工作或共同目标；
5. 其他关系或由Skill推荐。

接着确认谁主动、谁回应，以及最想表达的3个关系场景。不要先问动画参数或平台字段。

### 路线5｜动态或平台交付

先区分用户要的真实结果：

1. 把已有静态表情做成动态；
2. 建立可继续动画的真实拆件与源文件；
3. 整理成微信或其他平台候选包；
4. 动态成品和平台包都要；
5. 不确定，请帮我判断。

然后只核对现有母版、真实源文件、目标平台和当前状态。不要把有拆件说成有动画，也不要把上传包说成已通过。

## 5. 用户不知道时的默认路线

用户愿意交给Skill判断时，使用以下可撤回默认值，并明确说出采用了什么：

- 只有一个想法、没有图片：先生成2—3个母版候选；不直接做整套。
- 有一张普通角色图：把它作为身份参考，通过图像生成制作稳定母版与3张小样。
- 有真实同版本PSD／ORA等源文件：先核对真实性和版本，再局部编辑复用。
- 没说用途：暂按日常聊天候选处理。
- 没说平台：先做平台中立的透明候选，不上传。
- 没说静态或动态：先用静态母版与峰值姿势验证身份；通过后再进入动态。
- 没说数量：只做3张代表样；用户接受后再决定完整套装数量。
- 没说风格：保持原角色身份，只做必要的表情包化与小尺寸强化。
- 没说公开：保持`CANDIDATE / NOT_SUBMITTED / NOT_FORMAL`。

## 6. 访谈收口

信息足够后，用普通语言形成一段短结论，不再继续提问：

```text
我理解的方向是：

- 对象：……
- 现有材料：……
- 当前路线：……
- 主要用途：……
- 必须保持：……
- 第一轮结果：……
- 当前状态：候选，不上传／不公开

我现在先完成第一轮母版或3张小样；生成前会在当前线程保存完整提示词。
```

用户已经明确同意生产时，收口后直接进入当前路线；不要再增加一次形式化确认。若仍有两个会产生明显不同角色方向的承重解释，只指出那个具体差异并询问一次。

## 7. 第一轮交付

- 从零角色：2—3个母版候选，或用户已经明确方向时1个母版候选。
- 已有形象：暂定／正式母版说明加3张代表样。
- 扩展旧套：覆盖缺口加1—3张新增样本。
- 双角色：3个关系场景小样。
- 动态：1个完整动作的真实时间轴与循环候选，或一个`ANIMATION_READY`样本。
- 平台包：只取回／整理当前已有文件和缺口；未经授权不上传。

第一轮让用户看真实结果，不用更多访谈代替生产。
